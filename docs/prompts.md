**Инструмент:** Claude Code (модель Claude Opus 5.5, Anthropic), режим агента в приложении Claude для Windows. Агент сам создаёт файлы, запускает команды и проверяет сайт во встроенном браузере.

**Как читать журнал.** Запросы идут в порядке отправки. Под каждым номером — текст запроса целиком.

>
> Блоки строго по порядку (выбор — кнопками-«чипами»):
> 1. Зал.
> 2. Дата: только 14 дней вперёд от сегодняшней даты (список дат генерируй в JS).
> 3. Время начала (шаг 1 час, с 09:00 до 22:00 — чтобы уложиться в 23:00). Утренние часы будней помечены «−20%».
> 4. Число часов (1–8).
> 5. Итог: зал, дата и время, часы, скидка и стоимость крупно, в рублях. Выбор переносится в поля формы.
> 6. Занятые часы — массив в js/booking.js вида
>    `var BUSY = [{ hall: 'loft', day: 0, hours: [12, 13] }, { hall: 'newyear', date: '2026-12-05', hours: [10, 11] }, ...];`
>    (day — смещение от сегодняшнего дня, date — точная дата). Занятые часы показываются неактивными и зачёркнутыми. Нельзя выбрать время, если хотя бы один час брони занят.
> 7. Форма брони: name, phone, email (необязательно); поля hall, slot, hours, total_price только для чтения — их заполняет выбор слева; скрытые request_id, utm_source, utm_medium, utm_campaign, utm_content. Флажок согласия на обработку персональных данных со ссылкой на privacy.html — по умолчанию НЕ отмечен, без него форма не отправляется.
> 8. Связаться с нами: телефон, e-mail, адрес, режим работы, кнопки-ссылки Telegram и WhatsApp.
>
> Логика (js/form.js):
> - request_id генерируется как "REQ-" + crypto.randomUUID() при загрузке страницы.
> - UTM-метки читаются из location.search на любой странице и сохраняются в sessionStorage (чтобы не потеряться при переходах по сайту), при отправке подставляются в скрытые поля формы. Если меток нет — direct / none / not_set.
> - Валидация: name 2–60 символов, phone в формате +7 и 10 цифр, email — проверка формата, если заполнен. Ошибка подсвечивает поле и выводит текст под ним.
> - Отправка через fetch на URL приёмника (заглушка const ENDPOINT = "https://script.google.com/.../exec"). Кнопка на время отправки неактивна.
> - При ответе {"ok": true} — данные брони (без имени и телефона) сохраняются в sessionStorage и выполняется переход на thanks.html.
> - При ошибке — сообщение над кнопкой с телефоном студии.
>
> Аналитика (все события — через trackEvent() из analytics.js):
> - при выборе зала, даты, времени или часов — событие slot_select с параметрами hall_id, slot_date, slot_time, hours, total_price;
> - ошибки полей и сервера — form_error с параметрами field_name, error_type;
> - успешная отправка — generate_lead с параметрами lead_hall, hours, value, currency="RUB";
> - кнопки Telegram/WhatsApp: data-event="messenger_click" data-messenger="telegram|whatsapp"
> - телефон/email: data-event="contact_click" data-contact-type="phone|email"
> - кнопка отправки: data-event="cta_click" data-button-name="form_submit" data-page-section="booking_form"
>
> Выведи HTML, CSS, js/booking.js и js/form.js целиком. Не используй сторонние библиотеки для дат — только нативный Date.

## 10. Аналитика: js/analytics.js

**Запрос:**
> Напиши js/analytics.js, который подключается на всех страницах.
>
> Задачи:
> 1. Одна функция отправки trackEvent(name, params, callback), доступная как window.trackEvent. Её вызывают main.js, booking.js и form.js — напрямую gtag() в других файлах не вызывается. callback нужен перед переходом на другую страницу: он срабатывает, когда событие ушло, или через 1 секунду, если GA4 заблокирован.
> 2. Найти все элементы с data-event и при клике отправить событие, подставляя параметры из data-атрибутов в snake_case (data-button-name → button_name, data-page-section → page_section, data-hall-id → hall_id, data-network → network, data-messenger → messenger, data-contact-type → contact_type, data-genre → genre, data-photographer-id → photographer_id, data-photo-index → photo_index и т. д.). Числовые значения передавать числами.
> 3. Для `<details data-event="idea_open">` событие отправлять только при раскрытии, а не при закрытии.
> 4. Не передавать в GA4 имя, телефон, e-mail — ни в параметрах, ни в URL.
> 5. Имена событий и параметров — snake_case, значения не длиннее 100 символов.
> 6. Флаг DEBUG: при true ко всем событиям добавляется debug_mode, чтобы видеть их в DebugView.
>
> Выведи один файл js/analytics.js с комментариями по-русски.
